## 1. 产品概述

**一句话定位**：把留学申请所需的官方信息（院校排名、学费、语言要求、截止日期等）装进一个会「带着出处回答」的对话助手——用户用一句话提问，得到一句话回答，并可以当场核对回答来自哪个官方文件的哪一句。

**背景**：DIY 留学申请的信息散落在各校官网的多个页面（费用页、语言要求页、申请流程页……），中英文混杂、页面结构各异，翻找与比对的成本很高；通用搜索引擎与通用大模型存在两个致命问题——信息滞后（官网刚更新就查不到）与**回答不可溯源**（申请决策不能建立在「模型自己编的」信息上）。

**产品原则（优先级排序）**：
1. **正确性 > 流畅性**：宁可诚实拒答，绝不编造申请信息。
2. **可溯源**：每条文档类回答必须附带「来源文件 + 原文句子」。
3. **低成本可自托管**：全部本地运行，不依赖外部 SaaS。

---

## 2. 目标用户与典型场景

**目标用户**：DIY 留学申请者（无中介，自行搜集与核对院校信息）；次要用户：留学咨询从业者、院校信息整理者。

**典型场景**：

| 场景 | 用户故事 |
|---|---|
| 快速核对 | 「我想知道 LSE 的雅思要求是多少」——不翻官网，一句话得到答案并看到出处 |
| 跨校对比 | 「LSE 和 NYU 的 QS 排名分别是什么」——一次提问，多信息点合并回答 |
| 信息溯源 | 对答案存疑时，点击引用卡片看到原始文件与原文句子，自行验证 |
| 连续追问 | 「南洋理工的排名是多少？」→ 追问「它的截止日期呢？」——助手记得上一轮问的是南洋理工 |
| 私有文档问答 | 上传自己的 PDF/TXT 文档（如项目说明、申请材料）后针对其提问 |
| 深度推理 | 复杂对比问题切换到推理模型（DeepSeek-R1）获得更深入的分析 |

---

## 3. 痛点与价值

| 现状痛点 | 产品解决方式 |
|---|---|
| 信息分散在 5+ 个官网页面，中英文混杂 | 定向爬虫 + 本地向量库，一次提问聚合多页信息 |
| 通用大模型会「一本正经地编造」学费/截止日期 | 检索增强 + 负向题评测 + 诚实拒答机制 |
| 模型回答无法核对来源 | 「📚 引用来源」卡片：来源文件 + 命中答案的原句 |
| 商用问答产品按 token 收费、数据出域 | 本地 Qdrant + 本地 embedding，零外部 API 依赖、零检索成本 |
| 对话不连贯、跨题丢上下文 | 受控对话记忆窗口（最近 6 轮），指代正确 |

## 4. 产品目标与成功指标

| 指标 | 目标值 | 当前状态 | 度量方式 |
|---|---|---|---|
| 答案正确率（46 题题库） | 100% | 46/46 ✓ | 自动化评测脚本，按题判分 |
| 检索命中率 | 100% | 19/19 ✓ | 评测第一层指标 |
| 工具路由正确率 | 100% | 46/46 ✓ | 评测第二层指标 |
| 防编造能力 | 拒答且不编造金额/日期 | 5/5 负向题 ✓ | 双重条件判分（必须拒答 + 不得出现数字） |
| 引用卡片可用性 | 每条文档类回答附来源卡片，卡片只含 1~2 句支持句 | 已上线 | 展示层相似度选句 |
| 单问题端到端响应 | 一般问题 ≤ 30 秒 | 未正式压测 | 手动观测 |
| 运行成本（检索侧） | 零 API 成本 | 已达成 | 本地 fastembed + Qdrant |

> 评测体系本身就是产品的一部分：题库 46 题（18 排名题 + 16 文档题 + 7 混合题 + 5 负向题），每次改动检索/工具链路后必须重跑，任一指标下降视为发布阻断。

## 5. 功能需求

### FR-1 核心问答（P0，已上线）
**用户故事**：作为申请者，我输入一个留学问题，系统给我准确、可溯源的回答。
**验收标准**：
- 排名类问题（如「剑桥 QS 排名」）走排名数据工具回答，附数据更新时间；
- 文档类问题（如「LSE 雅思要求」）走本地文档检索回答，附引用来源卡片；
- 知识库中没有的信息必须诚实拒答（出现「未找到/没有」类表述），不得编造具体数字；
- 回答中不得泄露工具调用的中间 JSON 过程（默认隐藏）。

### FR-2 文档知识库（P0，已上线）
- 定向爬虫入库：抓取院校官网指定页面（已接入 LSE 5 个页面），每篇文档头部写入来源 URL 与抓取时间戳；
- 本地向量化：BAAI/bge-small-zh-v1.5 中文小模型 + Qdrant 本地库，跨语言检索（中文问题命中英文文档）；
- 上传入库：支持 PDF/TXT/DOCX/DOC，按「文件名 + 内容 MD5」去重，重复上传自动跳过；
- 验收：上传文档后即可针对其提问，重启服务后知识库无需重建。

### FR-3 引用溯源卡片（P0，已上线）
**用户故事**：作为申请者，我想知道答案出自哪个文件的哪句话，以决定是否采信。
**验收标准**：
- 每条文档类回答附带「📚 引用来源」卡片，列出引用号 + 来源文件名；
- 卡片只展示「命中答案的那句话」（最多 2 句支持句），不整块粘贴检索原文；
- 不展示抓取时间等与核对无关的元数据；
- 选句必须确定性强（本地 embedding 与回答的余弦相似度选句，非 LLM 随机抽取）。

### FR-4 模型切换（P0，已上线）
**用户故事**：作为用户，我想在「通用快答」与「深度推理」之间按需切换。
**验收标准**：
- 对话头部常驻可见的模型下拉（显示当前模型名与图标），无需进入设置面板；
- 候选：DeepSeek-V3（默认，通用快答）与 DeepSeek-R1（深度推理）；
- 切换后新对话以所选模型回答；历史对话保持原样可回看。

### FR-5 对话记忆与指代消解（P0，已上线）
- 受控记忆窗口：每会话保留最近 6 轮问答拼入上下文，超出窗口的最旧轮丢弃；
- 指代消解：追问「它的学费」时正确解析为上一轮主体；
- 历史回答截断至 500 字符控制 token 成本；
- 验收（已通过回归）：场景「南洋理工排名 → 截止日期」正确回答而非张冠李戴。

### FR-6 会话管理（P1，已上线）
- 历史会话列表：断线/刷新后完整恢复（消息 + 对话记忆）；
- 会话标题自动命名（取第一个问题前 20 字）；
- 密码登录可开关（配置环境变量启用，不配置则无登录）；
- 一键导出对话为 Markdown 文件（纯界面元素如欢迎横幅、引用卡片不入导出）。

### FR-7 品牌体验（P1，已上线）
- 品牌名「留学智库」+ 定制配色主题（奶油米色底 / 深森林绿 / 玫瑰马卡龙粉）；
- 首页欢迎横幅 + 3 个快捷问题按钮 + 导出按钮；
- 中文本地化界面文案。

## 6. 非功能需求

| 类别 | 要求 |
|---|---|
| 正确性 | 申请相关信息零编造（评测负向题 100% 通过）；评测体系作为发布门禁 |
| 成本 | 检索与选句环节零 API 调用（本地 embedding）；仅 LLM 回答消耗 token |
| 安全 | API 密钥仅存 .env（gitignore），推送前安全门检查（暂存区无密钥）；公开仓库内容经过审计（无内部信息） |
| 可用性 | 本地单机部署；Web 服务重启后知识库、会话历史不丢失 |
| 可维护性 | 检索/工具链路与展示层解耦（界面改动不触碰评测核心）；核心链路有协议级回归脚本 |
| 兼容性 | DeepSeek 偶发不按 OpenAI 协议输出工具调用（约 1/5 轮）时系统自动兼容解析，不向用户泄露原始 XML |

## 7. 技术方案概述（摘要）

- **架构**：主 ChatAgent（ReAct 工具调度）+ 文档子 Agent（DocChatAgent 检索问答）+ 排名数据工具，多智能体协作；
- **模型**：DeepSeek V3/R1（OpenAI 兼容协议），Web 端会话级切换；
- **检索**：向量检索全量召回（语料规模小，截断反而漏命中）+ 展示层相似度选句；
- **前端**：Chainlit 2.12（Socket 协议 + SQLite 数据层）；
- 详细技术决策与踩坑记录见 `docs/interview.md`。

## 9. 风险与开放问题

| 风险/问题 | 影响 | 应对 |
|---|---|---|
| 官网反爬升级导致语料无法更新 | 知识库时效性下降 | 手工导出 + 上传兜底；爬虫限速合规抓取 |
| 排名数据一年一更 | 回答可能滞后 | 数据文件带更新时间戳，回答中明示；update_rankings.py 支持一键更新 |
| 单机部署无法多人共享 | 仅本人使用 | 路线图 P1 线上部署 |
| 跨语言检索相似度整体偏低（0.5~0.7） | 存在漏召回风险 | 小语料全量召回 + 评测兜底；语料扩大后需重新设计召回策略 |
